## 项目定位

`LinkLabel 标注平台｜赋能图片识别算法的数据标注与质检平台｜Java、Spring Boot、MyBatis/MyBatis-Plus、MySQL、Redis、Redisson、OSS、EasyExcel｜后端独立负责人`

## 业务背景

LinkLabel 是面向图片识别算法训练与迭代的数据标注平台，覆盖项目管理、数据集管理、图片上传、模板配置、人工标注、混合标注、质检、问题流转、数据导出和权限协同等核心能力，用于支撑算法侧高质量训练数据的生产和交付。

## 个人职责

独立负责平台后端从 0 到 1 的设计与开发，完成项目、数据集、模板、标注、质检、导出、权限与基础设施能力建设，并持续支撑业务迭代和联调落地。

## 技术难点

- 标注场景复杂，既要支持字段标注、明细标注，也要支持表格型混合标注、列表区混合标注和定责标注等多形态数据结构
- 标注流程不仅是“保存结果”，还要兼顾质检结果、缓存一致性、模板回填和问题件流转
- 平台属于多角色协同系统，需要在项目、数据集、图片等多层粒度做权限隔离和操作控制
- 图片上传、压缩包导入、导出报表等任务存在 IO 密集和批量处理特征，需要异步化与线程池隔离，避免影响核心标注链路

## 面试可展开亮点

### 1. 为什么这是平台，而不是单功能系统

可讲清楚该项目不是一个简单的“图片上传 + 保存标注”工具，而是覆盖：

- 项目管理
- 数据集管理
- 模板管理
- 图片上传与压缩包导入
- 标注与质检
- 问题件流转
- 数据导出与交付
- 成员与角色权限

这能体现你做的是平台型系统，而不是页面接口开发。

### 2. 标注模型抽象

这是本项目最有含金量的技术亮点之一。

可重点讲：

- 为什么要把固定区、动态区、表格区、列表区统一到一套结构里
- 为什么列表区使用 `List<Map<String, Object>>`
- 为什么字段级 `comment` 要同时进入保存结果、质检结果与 Redis 缓存
- 如何保证模板定义、标注结果、回填结果三者结构一致

### 3. 权限与协同

可讲：

- 为什么平台需要项目 owner / 管理员 / 标注员 / 质检的分层权限
- 为什么权限校验不仅发生在 controller，还要落实到项目、数据集、图片等操作边界
- 如何避免“退出项目后仍可操作数据”“管理员误改高权限成员”等问题

### 4. 异步与稳定性

可讲：

- 为什么上传、批处理、导出不能与核心标注接口共用同一条执行链路
- 为什么要拆 `customThreadPoolExecutor` 和 `exportThreadPoolExecutor`
- 为什么上传过程要结合 Redis 记录状态
- 为什么导出任务要异步执行并做队列容量与拒绝策略控制
