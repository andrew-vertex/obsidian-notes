# Java 转 AI 应用开发学习进度与实践清单

本页只记录可验证的学习成果。阅读状态在各专题页维护，这里聚合阶段级里程碑。


## Key Takeaways

- 勾选前必须有证据链接，不以“看过文章”作为完成标准。
- RAG 和 Agent 先独立验收，再做综合项目。
- 评测、安全和观测从第一个实验开始建设。

## 阶段里程碑

### 阶段 0：定位

- [ ] 能区分 AI 应用工程、模型算法和 AI Coding。
- [ ] 写出已有 Java 后端能力的迁移清单。
- [ ] 明确 Python 的最低学习范围。

### 阶段 1：LLM 调用层

- [ ] 完成一个非流式 Java 调用。
- [ ] 完成一个 SSE 流式调用并记录 TTFT。
- [ ] 验证 JSON Schema、Function Calling 或 Strict Structured Outputs。
- [ ] 注入超时、429、500 和截断响应，验证重试与降级。
- [ ] 将供应商 SDK 隔离在自定义领域接口之后。

### 阶段 2：Prompt 与 Context

- [ ] Prompt 已外置、版本化并可回滚。
- [ ] System 指令和用户输入使用明确边界隔离。
- [ ] 有 Token 预算与上下文淘汰策略。
- [ ] 建立首批 Golden Set，并在 Prompt 变更时回归。

### 阶段 3：RAG

- [ ] 能查看解析、Chunk、召回、Rerank 和最终上下文。
- [ ] 对比固定长度切分与结构化切分。
- [ ] 对比向量检索、BM25 和混合检索。
- [ ] 分开记录 Hit Rate@K/MRR 与 Faithfulness/Answer Relevance。
- [ ] 验证租户、ACL、版本和增量更新。

### 阶段 4：Agent

- [ ] 注册并调用至少 3 个只读工具。
- [ ] 对工具参数做类型、权限和业务校验。
- [ ] 设置最大步数、总超时和 Token/成本预算。
- [ ] 能从持久化检查点恢复中断任务。
- [ ] 高风险工具执行前必须人工审批。

### 阶段 5：工程化

- [ ] LLM 调用不占用长事务和数据库连接。
- [ ] 有模型 fallback、熔断、限流和指数退避。
- [ ] Trace 关联 Prompt、模型、检索和工具版本。
- [ ] 看板可见 TTFT、总延迟、Token、成本和失败率。
- [ ] 输入、日志和 Trace 有 PII 脱敏与留存策略。

### 阶段 6：项目

- [ ] 完成一个可部署项目和架构说明。
- [ ] 维护 50～200 条起步 Golden Set。
- [ ] 完成一次压力测试、故障注入和安全测试。
- [ ] 写出一份基于真实指标的项目复盘。
