# 第一章 初识智能体
## 1.1 什么是智能体 (Agent)？

- **定义**：任何能够通过**传感器**感知环境，并自主地通过**执行器**采取行动，以达成特定目标的实体。
    
- **核心模式**：感知 (Perceive) $\rightarrow$ 决策 (Decide) $\rightarrow$ 行动 (Act) 的闭环。
    
- **智能体的四大基本要素**：

	- **环境 (Environment)**：智能体所处的外部世界（可以是物理的，如道路；也可以是虚拟的，如金融市场）。
	    
	- **传感器 (Sensors)**：获取环境信息的通道（如摄像头、雷达、API 数据流）。
	    
	- **执行器 (Actuators)**：改变环境状态的工具（如机械臂、方向盘、代码/服务调用）。
	    
	- **自主性 (Autonomy)**：**智能的核心**。不只是被动响应，而是能基于感知和内部状态进行**独立决策**，以达成预设目标。

### 1.1.1 传统视角下的智能体（演进路线）

传统智能体经历了从“被动反应”到“主动学习”的演进，主要分为以下五种范式：

1. **简单反射智能体 (Simple Reflex Agent)**
    
    - **决策核心**：由工程师硬编码的“条件-动作”规则（如：若温度过高 $\rightarrow$ 启动制冷）。
        
    - **局限**：无记忆、无预测能力，完全依赖当前瞬时感知，无法应对复杂上下文。
        
2. **基于模型的反射智能体 (Model-Based Reflex Agent)**
    
    - **核心引入**：**世界模型 (World Model)** 与内部状态。
        
    - **优势**：拥有初级“记忆”，能追踪当前无法直接感知的信息（如：自动驾驶汽车在隧道中仍能推测前车位置）。
        
3. **基于目标的智能体 (Goal-Based Agent)**
    
    - **核心引入**：明确的**目标**与**规划 (Planning)**。
        
    - **优势**：不再是被动反应，而是主动且有预见性地选择行动，利用搜索算法规划最优路径（如：GPS 导航）。
        
4. **基于效用的智能体 (Utility-Based Agent)**
    
    - **核心引入**：**效用值**（代表满意度高低）。
        
    - **优势**：能够在多个冲突的目标之间进行权衡（如：时间最短 vs 路径最省油），实现更接近人类的理性决策（最大化期望效用）。
        
5. **学习型智能体 (Learning Agent)**
    
    - **核心引入**：**学习元件** + 性能元件。
        
    - **优势**：不依赖人类先验知识，通过与环境互动（如**强化学习 RL**）获取奖励并自我进化（如：AlphaGo Zero）。
        

### 1.1.2 大语言模型 (LLM) 驱动的新范式

- **本质变革**：从传统智能体的“显式编程、确定且有边界”，转向 LLM 的“海量数据预训练、**隐式世界模型**与**涌现能力**”。
    
- **核心优势**：可以直接理解高层级、模糊且充满上下文的**自然语言指令**。

#### LLM 智能体的三大核心特性（以“智能旅行助手”为例）

1. **规划与推理 (Planning & Reasoning)**：能够将“规划厦门之旅”等模糊宏观目标，自发拆解为逻辑清晰的子任务链。
    
2. **工具使用 (Tool Use)**：识别到自身信息缺口时，能主动调用外部工具（如：调用天气 API 并根据“预报有雨”倾向推荐室内行程）。
    
3. **动态修正 (Dynamic Correction)**：能将用户的最新反馈（如“超出预算”）作为新约束，实时调整并重塑后续的行为与推荐。
    

- **结语**：AI 正在从“编写代码开发**专用自动化工具**”，转向“引导通用大脑去规划和行动的**自主解决问题系统**”。


### 1.1.3 智能体的类型

可以从三个互补的维群对智能体进行分类：

#### （1）基于内部决策架构的分类

- **划分依据**：内部决策架构的复杂程度（源自《AIMA》经典理论）。
    
- **演进阶梯**：反射智能体 $\rightarrow$ 模型式智能体 $\rightarrow$ 基于目标的智能体 $\rightarrow$ 基于效用的智能体。
    
- **元能力**：**学习能力**（可赋予上述任何一类智能体，使其通过经验自我改进）。

> 
> 现代 LLM 智能体在 **“思考（规划/Reasoning） $\rightarrow$ 行动与观察（反应/Acting & Observing）”** 的循环中运作。它将宏大任务拆解为一系列“规划-反应”的微循环，巧妙融合了两者的优势。

#### （3）基于知识表示的分类（AI 文化的半世纪辩论）

- **符号主义 AI (Symbolic AI) —— “图书管理员”**
    
    - **核心**：智能源于对人类可读符号（如词语、概念）的**逻辑操作**（如规则库、知识图谱）。
        
    - **优缺点**：高透明度、可完整追溯推理步骤；但系统脆弱，存在“知识获取瓶颈”，难以应对模糊和充满例外的现实世界。
        
- **亚符号主义 AI (Sub-symbolic AI) —— “牙牙学语的孩童”**
    
    - **核心**：知识隐式分布于**神经网络**的连接权重中，是从海量数据中学习到的统计模式。
        
    - **优缺点**：强大的模式识别与非结构化数据（图像、声音）处理能力，鲁棒性强；但属于不可解释的“黑箱”，逻辑推理弱，易产生幻觉。
        
- **神经符号主义 AI (Neuro-Symbolic AI) —— “大和解范式”**
    
    - **核心**：融合上述两者，弥合感知和认知、直觉与理性。完美对应丹尼尔·卡尼曼的**双系统理论**：
        
        - **系统 1（快思考）**：直觉、并行思维 $\rightarrow$ 对应**亚符号主义**的模式识别。
            
        - **系统 2（慢思考）**：条理、逻辑推理 $\rightarrow$ 对应**符号主义**的逻辑操作。
            

> **LLM 智能体的神经符号实践**：
> 
> 其内核是一个巨大的神经网络（亚符号，负责直觉和语言生成），但在工作时会输出结构化的中间步骤、思考计划或 API 调用（符号，负责可操作的逻辑推理），实现了感知与认知的初步融合。

## 1.2 智能体的构成与运行原理

### 1.2.1 任务环境定义

#### 1. PEAS 模型

在人工智能领域，通常使用 **PEAS 模型**来精确描述和规约智能体的任务环境：

- **P**erformance (性能度量)：评估智能体表现的标准。
    
- **E**nvironment (环境)：智能体所处的外部世界。
    
- **A**ctuators (执行器)：智能体用来改变环境的工具/接口。
    
- **S**ensors (传感器)：智能体用来接收环境信息的通道。

在实践中，环境的数字特性直接决定了智能体必须具备的核心能力：

|**环境特性**|**原文典型实例**|**带来的挑战**|**对智能体的设计要求 (Core Requirements)**|

### 1.2.2 智能体的运行机制：智能体循环 (Agent Loop)
智能体并非一次性完成任务，而是通过智能体循环 (Agent Loop)这一持续闭环与环境动态交互，从初始状态向目标状态演进 。

  <img src="https://raw.githubusercontent.com/datawhalechina/Hello-Agents/main/docs/images/1-figures/1757242319667-5.png" alt="图片描述" width="90%"/>

</div>

1. **感知 (Perception)**：Loop 起点。传感器接收来自环境的**观察 (Observation)** 信息（如用户指令或上一步行动的状态变化反馈）。
    
2. **思考 (Thought)**：决策核心（由 LLM 驱动的内部推理核心），细分为两个关键环节：
    
    - **规划 (Planning)**：结合记忆与当前观察，拆解复杂目标，制定/调整行动计划。
        
    - **工具选择 (Tool Selection)**：决定调用哪个外部工具，并确定具体参数。
        
3. **行动 (Action)**：执行器执行具体操作（如调用 API），改变环境状态并催生新的“观察”反馈，进入下一轮循环。
	
  
$$\text{感知 (Perception)} \rightarrow \text{思考 (Thought)} \rightarrow \text{行动 (Action)} \rightarrow \text{环境改变} \rightarrow \text{新观察 (Observation)}$$

### 1.2.3 智能体的感知与行动（交互协议）

在工程实践中，通过**结构化的交互协议**来规范 LLM 与环境的信息交换以有效驱动智能体循环。
智能体的每一次结构化输出与环境交互遵循以下范式：

> - **Thought（思考）**：内部决策的“快照”。用自然语言阐述情境分析、反思与下一步规划。
>     
> - **Action（行动）**：具体的指令。通常表现为**函数/API 调用**（如 `get_weather("北京")`）。
>     
> - **Observation（观察）**：环境的反馈。感知系统充当传感器，将工具返回的机器数据（如复杂 JSON）提炼封装为 LLM 易读的**自然语言文本**，并作为下一轮推理的输入。

### 1.2.3 工程落地：Thought-Action-Observation 交互协议

在工程实践中，为了让大语言模型（LLM）有效驱动智能体循环，需要一套明确的结构化的**交互协议 (Interaction Protocol)**，将内部推理与外部工具调用规范化。智能体的每一次结构化输出与环境交互遵循以下范式 ：

| **协议组件**                                | **对应循环阶段**          | **展现形式与内容**                                                                | **原文典型工程示例**                |
| --------------------------------------- | ------------------- | -------------------------------------------------------------------------- | --------------------------- |
| **Thought**<br><br>  <br><br>_(思考)_     | **思考 (Thought)**    | **内部决策的“快照”**。用自然语言分析当前情境、反思上一步结果并规划下一步行动 。                                | _“用户想知道北京的天气。我需要调用天气查询工具。”_ |
| **Action**<br><br>  <br><br>_(行动)_      | **行动 (Action)**     | **对外部世界的指令**。通常表现为函数或 API 调用，由外部**解析器 (Parser)** 捕捉并执行 。                   | `get_weather("北京")`         |
| **Observation**<br><br>  <br><br>_(观察)_ | **感知 (Perception)** | **环境的精简反馈**。感知系统充当传感器，将工具返回的机器数据（如复杂 JSON）提炼封装为 LLM 易读的自然语言文本，并作为下一轮推理的输入。 | _“北京当前天气为晴，气温25摄氏度，微风。”_    |

> **核心价值**：通过这一由 **Thought $\rightarrow$ Action $\rightarrow$ Observation** 构成的严谨文本循环，LLM 智能体成功将内部的**语言推理能力**，与外部环境的**真实信息**和**工具操作能力**有效地结合在了一起 。

## 1.3 动手体验：5 分钟实现第一个智能体

### 1.3.1 核心目标与准备工作

- **实践目标**：从零开始构建一个可以执行多步任务的**智能旅行助手**。
    
- **具体任务**：_“查询今天北京的天气，然后根据天气推荐一个合适的旅游景点。”_（需要展现任务分解与前后依赖的逻辑规划能力）。
    
- **依赖安装**：
    
    Bash
    
    ```
    pip install requests tavily-python openai
    ```
    

#### 1. 指令模板 (System Prompt)

提示工程是驱动 LLM 决策的说明书。需要严格规范其**角色**、**可用工具**与**输出格式**：

Python

```
AGENT_SYSTEM_PROMPT = """
你是一个智能旅行助手。你的任务是分析用户的请求，并使用可用工具一步步地解决问题。

# 可用工具:
- `get_weather(city: str)`: 查询指定城市的实时天气。
- `get_attraction(city: str, weather: str)`: 根据城市和天气搜索推荐的旅游景点。

# 输出格式要求:
你的每次回复必须严格遵循以下格式，包含一对Thought和Action：
Thought: [你的思考过程和下一步计划]
Action: [你要执行的具体行动]

Action的格式必须是以下之一：
1. 调用工具：function_name(arg_name="arg_value")
2. 结束任务：Finish[最终答案]
"""
```

#### 2. 工具定义与注册

- **工具 1 (get_weather)**：通过调用 `wttr.in` API 获取指定城市的真实天气状况，解析 JSON 并转化为自然语言。
    
- **工具 2 (get_attraction)**：利用 `TavilySearch` API，根据城市和天气在互联网上搜索并整合出优化后的景点推荐。
    
- **工具注册**：将函数统一放入字典中以便后续动态调用。
    
    Python
    
    ```
    available_tools = {
        "get_weather": get_weather,
        "get_attraction": get_attraction,
    }
    ```
    

### 1.3.2 接入大语言模型 (LLM)

通过封装 OpenAI SDK，实现一个通用的、兼容 OpenAI 接口规范的 LLM 客户端（可无缝切换 OpenAI、Azure 或本地的 Ollama/vLLM）。

Python

```
from openai import OpenAI

class OpenAICompatibleClient:
    def __init__(self, model: str, api_key: str, base_url: str):
        self.model = model
        self.client = OpenAI(api_key=api_key, base_url=base_url)

    def generate(self, prompt: str, system_prompt: str) -> str:
        messages = [
            {'role': 'system', 'content': system_prompt},
            {'role': 'user', 'content': prompt}
        ]
        response = self.client.chat.completions.create(model=self.model, messages=messages)
        return response.choices[0].message.content
```

# prompt_history 初始化存储用户输入
for i in range(5):  # 最大循环 5 次

### 1.3.4 运行案例分析：三轮循环的解剖

整个执行流程完美诠释了智能体自主解决问题的核心逻辑：

- **循环 1**：
    
    - **Thought**：拆解任务，意识到必须先查天气。
        
    - **Action**：调用 `get_weather(city="北京")`。
        
    - **Observation**：环境反馈 _“北京当前天气:Sunny，气温26摄氏度”_。
        
- **循环 2**：
    
    - **Thought**：将上一轮的观察纳入上下文，现在可以基于晴天推荐景点了。
        
    - **Action**：调用 `get_attraction(city="北京", weather="Sunny")`。
        
    - **Observation**：工具返回颐和园、长城等搜索结果。
        
- **循环 3**：
    
    - **Thought**：信息已收集齐备，准备输出最终答复。
        
    - **Action**：`Finish[...]` 退出循环，向用户交付结果。
        

> **小结**：智能体的工程精髓在于**工具**和**提示工程**的有机结合。通过这个简单的旅行助手，我们直观地验证了基于 `Thought-Action-Observation` 范式所具备的四项基本能力：**任务分解、工具调用、上下文理解和结果合成**。
