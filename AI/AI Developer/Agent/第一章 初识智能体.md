# 第一章 初识智能体
## 1.1 什么是智能体 (Agent)？

- **定义**：任何能够通过**传感器**感知环境，并自主地通过**执行器**采取行动，以达成特定目标的实体。
    
- **核心模式**：感知 (Perceive) $\rightarrow$ 决策 (Decide) $\rightarrow$ 行动 (Act) 的闭环。
    
- **智能体的四大基本要素**：

	- **环境 (Environment)**：智能体所处的外部世界（可以是物理的，如道路；也可以是虚拟的，如金融市场）。
	    
	- **传感器 (Sensors)**：获取环境信息的通道（如摄像头、雷达、API 数据流）。
	    
	- **执行器 (Actuators)**：改变环境状态的工具（如机械臂、方向盘、代码/服务调用）。
	    
	- **自主性 (Autonomy)**：**智能的核心**。不只是被动响应，而是能基于感知和内部状态进行**独立决策**，以达成预设目标。

### 1.1.1 传统视角下的智能体（演进路线）

传统智能体经历了从“被动反应”到“主动学习”的演进，主要分为以下五种范式：

1. **简单反射智能体 (Simple Reflex Agent)**
    
    - **决策核心**：由工程师硬编码的“条件-动作”规则（如：若温度过高 $\rightarrow$ 启动制冷）。
        
    - **局限**：无记忆、无预测能力，完全依赖当前瞬时感知，无法应对复杂上下文。
        
2. **基于模型的反射智能体 (Model-Based Reflex Agent)**
    
    - **核心引入**：**世界模型 (World Model)** 与内部状态。
        
    - **优势**：拥有初级“记忆”，能追踪当前无法直接感知的信息（如：自动驾驶汽车在隧道中仍能推测前车位置）。
        
3. **基于目标的智能体 (Goal-Based Agent)**
    
    - **核心引入**：明确的**目标**与**规划 (Planning)**。
        
    - **优势**：不再是被动反应，而是主动且有预见性地选择行动，利用搜索算法规划最优路径（如：GPS 导航）。
        
4. **基于效用的智能体 (Utility-Based Agent)**
    
    - **核心引入**：**效用值**（代表满意度高低）。
        
    - **优势**：能够在多个冲突的目标之间进行权衡（如：时间最短 vs 路径最省油），实现更接近人类的理性决策（最大化期望效用）。
        
5. **学习型智能体 (Learning Agent)**
    
    - **核心引入**：**学习元件** + 性能元件。
        
    - **优势**：不依赖人类先验知识，通过与环境互动（如**强化学习 RL**）获取奖励并自我进化（如：AlphaGo Zero）。
        

### 1.1.2 大语言模型 (LLM) 驱动的新范式

- **本质变革**：从传统智能体的“显式编程、确定且有边界”，转向 LLM 的“海量数据预训练、**隐式世界模型**与**涌现能力**”。
    
- **核心优势**：可以直接理解高层级、模糊且充满上下文的**自然语言指令**。

#### LLM 智能体的三大核心特性（以“智能旅行助手”为例）

1. **规划与推理 (Planning & Reasoning)**：能够将“规划厦门之旅”等模糊宏观目标，自发拆解为逻辑清晰的子任务链。
    
2. **工具使用 (Tool Use)**：识别到自身信息缺口时，能主动调用外部工具（如：调用天气 API 并根据“预报有雨”倾向推荐室内行程）。
    
3. **动态修正 (Dynamic Correction)**：能将用户的最新反馈（如“超出预算”）作为新约束，实时调整并重塑后续的行为与推荐。
    

- **结语**：AI 正在从“编写代码开发**专用自动化工具**”，转向“引导通用大脑去规划和行动的**自主解决问题系统**”。


### 1.1.3 智能体的类型

可以从三个互补的维群对智能体进行分类：

#### （1）基于内部决策架构的分类

- **划分依据**：内部决策架构的复杂程度（源自《AIMA》经典理论）。
    
- **演进阶梯**：反射智能体 $\rightarrow$ 模型式智能体 $\rightarrow$ 基于目标的智能体 $\rightarrow$ 基于效用的智能体。
    
- **元能力**：**学习能力**（可赋予上述任何一类智能体，使其通过经验自我改进）。

> **LLM 智能体的混合微循环**：
> 
> 现代 LLM 智能体在 **“思考（规划/Reasoning） $\rightarrow$ 行动与观察（反应/Acting & Observing）”** 的循环中运作。它将宏大任务拆解为一系列“规划-反应”的微循环，巧妙融合了两者的优势。

#### （3）基于知识表示的分类（AI 文化的半世纪辩论）

- **符号主义 AI (Symbolic AI) —— “图书管理员”**
    
    - **核心**：智能源于对人类可读符号（如词语、概念）的**逻辑操作**（如规则库、知识图谱）。
        
    - **优缺点**：高透明度、可完整追溯推理步骤；但系统脆弱，存在“知识获取瓶颈”，难以应对模糊和充满例外的现实世界。
        
- **亚符号主义 AI (Sub-symbolic AI) —— “牙牙学语的孩童”**
    
    - **核心**：知识隐式分布于**神经网络**的连接权重中，是从海量数据中学习到的统计模式。
        
    - **优缺点**：强大的模式识别与非结构化数据（图像、声音）处理能力，鲁棒性强；但属于不可解释的“黑箱”，逻辑推理弱，易产生幻觉。
        
- **神经符号主义 AI (Neuro-Symbolic AI) —— “大和解范式”**
    
    - **核心**：融合上述两者，弥合直觉与理性。完美对应丹尼尔·卡尼曼的**双系统理论**：
        
        - **系统 1（快思考）**：直觉、并行思维 $\rightarrow$ 对应**亚符号主义**的模式识别。
            
        - **系统 2（慢思考）**：条理、逻辑推理 $\rightarrow$ 对应**符号主义**的逻辑操作。
            

> **LLM 智能体的神经符号实践**：
> 
> 其内核是一个巨大的神经网络（亚符号，负责直觉和语言生成），但在工作时会输出结构化的中间步骤、思考计划或 API 调用（符号，负责可操作的逻辑推理），实现了感知与认知的初步融合。

## 1.2 智能体的构成与运行原理

### 1.2.1 任务环境定义

#### 1. PEAS 模型

在 AI 中，通常使用 **PEAS 模型**来精确描述和规约智能体的任务环境：

- **P**erformance (性能度量)：评估智能体表现的标准。
    
- **E**nvironment (环境)：智能体所处的外部世界。
    
- **A**ctuators (执行器)：智能体用来改变环境的工具/接口。
    
- **S**ensors (传感器)：智能体用来接收环境信息的通道。
    

#### 2. 数字环境的四大复杂特性

LLM 智能体所处的数字环境通常具有以下特征，直接影响其设计：

- **部分可观察 (Partially Observable)**：智能体无法一次性获取全量实时信息，必须具备**记忆**与**探索**能力。
    
- **随机性 (Stochastic)**：相同行动的结果不可完全预测（如机票价格瞬息万变），要求智能体能**处理不确定性**。
    
- **多智能体 (Multi-agent)**：环境中存在其他行动者（如其他用户或调价系统），其行为会动态改变环境状态。
    
- **序贯且动态 (Sequential & Dynamic)**：
    
    - _序贯_：当前的决策会持续影响未来的状态。
        
    - _动态_：环境在智能体“深思熟虑”的同时也在自主发生变化。
        

### 1.2.2 智能体的运行机制：智能体循环 (Agent Loop)

智能体通过持续的闭环与环境交互，推动任务从初始状态向目标状态演进：

$$\text{感知 (Perception)} \rightarrow \text{思考 (Thought)} \rightarrow \text{行动 (Action)} \rightarrow \text{环境改变} \rightarrow \text{新观察 (Observation)}$$

1. **感知 (Perception)**：起点。传感器捕获环境的**观察 (Observation)** 信息（如用户指令或上一步行动的反馈）。
    
2. **思考 (Thought)**：决策核心（由 LLM 驱动），细分为两个关键环节：
    
    - **规划 (Planning)**：结合记忆与当前观察，拆解复杂目标，制定/调整行动计划。
        
    - **工具选择 (Tool Selection)**：决定调用哪个外部工具，并确定具体参数。
        
3. **行动 (Action)**：执行器执行具体操作（如调用 API），改变环境状态并催生新的“观察”，进入下一轮循环。
    

### 1.2.3 智能体的感知与行动（交互协议）

在工程实践中，通过**结构化的交互协议**来规范 LLM 与环境的信息交换。智能体的单次输出通常包含以下标准格式：

> - **Thought（思考）**：内部决策的“快照”。用自然语言阐述情境分析、反思与下一步规划。
>     
> - **Action（行动）**：具体的指令。通常表现为**函数/API 调用**（如 `get_weather("北京")`）。
>     
> - **Observation（观察）**：环境的反馈。感知系统充当传感器，将工具返回的机器数据（如复杂 JSON）提炼封装为 LLM 易读的**自然语言文本**，并作为下一轮推理的输入。
